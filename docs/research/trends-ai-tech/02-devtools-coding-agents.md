## TL;DR

1. **Getting coding agents to talk to each other is the strongest single theme of the quarter.** Anthropic shipped native cross-session messaging in Claude Code. At least six independent "let Claude/Codex/OpenCode message each other" Show HNs appeared, and the fleet orchestrators (Orca, Paperclip, OpenRig) dominate GitHub trending. This sits squarely on Agent Relay's track.
2. **The fight has moved from models to harnesses.** DeepSeek Harness (266k stars in about 11 weeks), OpenCode 2.0's background-service rewrite, Vercel's fx, Cusp, Mercury CLI going open source, and HN threads on "harness engineering" all point the same way. The agent runtime is turning into an embeddable, long-running service, which is the shape of an actor.
3. **The loudest complaints are about usage limits and metering.** Claude Code quota drain (GitHub issues from Oct 16 on), a confirmed ~1.7x five-hour-limit drain through the Agents SDK, 429s that are really spend caps, and N parallel agents sharing one rate limit.
4. **Devtools are reorganizing around agents.** Cursor's Agent SDK (Oct 20) and Origin marketplace (Oct 13), Entire's agent-first Git forge (Oct 26), Codex memory v2 (Oct 27), and AWS AgentCore CLI 1.0 (Oct 28) all shipped inside about two weeks.
5. **The supporting layers around agents are what trends:** memory (claude-mem, ai-memory, hindsight), context trimming (context-mode, codegraph, graphify), sandboxing and security (NVIDIA OpenShell, cloudflare/security-audit-skill), and attention management (coucou, nodeterm, Offrun).

## 1. Agent-to-agent messaging between coding agents (most relevant to this event)

### Verified
- **Claude Code cross-session messaging.** Sessions find each other with `ListAgents` and send with `SendMessage`. Requires v2.1.224+ on macOS, Linux, and WSL 2, and v2.1.234+ on native Windows. A message is text Claude writes, "never your conversation history or files." Source: Claude Code What's New, 2026-w32 (about early August, so **[background]** at the edge of the window): https://code.claude.com/docs/en/whats-new/2026-w32 and docs https://code.claude.com/docs/en/cross-session-messaging . A later changelog entry extended it to Bedrock, Vertex, and Foundry: https://code.claude.com/docs/en/changelog
  - **Correction (re-checked 2026-10-29): the built-in feature is no longer local-only, and it already pushes.** The current docs say Claude can "reach your sessions on other machines or in the cloud." Those messages go through Anthropic servers over Remote Control and need v2.1.225+ plus a claude.ai sign-in. Claude "can't find those sessions with an API key or on Amazon Bedrock... and Microsoft Foundry." Delivery is push: the receiving Claude reads a message "between tool calls during an active turn," and an idle session starts a new turn. The limits that still apply: it reaches only **your own** sessions (the socket is restricted to your OS user), it is **Claude Code only**, it is **"Plain text only"**, it queues at most 50 accepted messages, and cloud sessions cannot reply with `SendMessage`. https://code.claude.com/docs/en/cross-session-messaging
- **Claude Code agent teams.** A lead session coordinates teammates that "communicate directly with each other," with shared tasks: https://code.claude.com/docs/en/agent-teams
- **Show HN wave of DIY inter-agent buses** (post dates and scores re-checked against the HN Firebase API on 2026-10-29):
  - *Ax / Agent Exchange* (2026-09-23, 4 pts): local Go broker, Unix sockets, and a SQLite mailbox. Supports Claude Code, Codex CLI, Grok Build, OpenCode, and Pi. The author says he wanted Claude Code's cross-session messaging "between Claude, Codex, and OpenCode." https://news.ycombinator.com/item?id=49816738
  - *agent-mesh* (2026-10-11, 4 pts; posted as "A hub that controls all your coding agents in one place," not a Show HN): "if codex figures something out, i want claude to know it, I'm the one copying it across." https://news.ycombinator.com/item?id=50047701 (repo has 8 stars)
  - *Concord* (MCP + CLI to claim work and message live; 2026-08-27, 9 pts): https://news.ycombinator.com/item?id=49464704
  - *agent-talk* (55 pts, 2026-07-16) **[background]**: https://news.ycombinator.com/item?id=48936534 . *Claude Code and Codex can have real-time conversation via Git* (116 pts, 79 comments, 2026-05-31) **[background]**: https://news.ycombinator.com/item?id=48345837
  - *"Show HN: Agent-relay for multi-vendor coding sessions"* (2026-10-27, 8 pts). **This is a separate MIT prototype, `saranyan/agent-relay` (10 stars), not agentrelay.com.** It uses a leader/follower controller and a durable on-disk log: https://news.ycombinator.com/item?id=50262407 (mirror: https://hn.today/s/show-hn-agent-relay-for-multi-vendor-coding-sessions)
- **Comments in those threads say the hard part is something other than transport.** "The friction of agents having to monitor CLI is just too annoying right now... a harness problem... a protocol problem" (agent-talk thread). Another: "the real problem tends to be identity and trust across sessions." A stale-monitor worry: "a new message triggering a few stale instances... would result in cache misses and a hefty usage bill." A skeptic in the Git thread: "Claude can directly drive Codex or Codex can drive Claude... It's unclear what value this intermediary brings." The first three quotes are in the agent-talk thread (https://news.ycombinator.com/item?id=48936534). The skeptic quote is in the Git thread (https://news.ycombinator.com/item?id=48345837). All four were re-checked verbatim via the HN Algolia API. Both threads are **[background]**: they predate August.
- **Agent Relay itself** (`AgentWorkforce/relay`): 1,059 stars, 95 forks, Apache-2.0. v14.0.0 shipped 2026-10-13. GitHub releases `probe-v15.0.0` (2026-10-29 07:44 UTC) and `probe-v15.0.1` (2026-10-30 04:48 UTC) are titled "Agent Relay core 15.0.x". They are the Rust core binary that `relay init` downloads and checks against a `.sha256` sidecar. The npm package `@agent-relay/sdk` is still at 14.0.0 (`npm view`, 2026-10-30 UTC). The README says `relay init` "starts a private server on this machine (no account needed), finds the coding agents you have installed (Claude Code, Codex, OpenCode, Grok CLI, Pi, Devin), and adds Relay to them," and that each session joins as `<tool>-<folder>`. It also says agents "can run on different machines and still coordinate in the same workspace." The README pitches Messaging (channels, threads, DMs, real-time events across machines), Integrations exposed as a virtual filesystem (relayfile), Shared Sessions, and Flows (TypeScript workflows with deterministic checks and human gates). Opening line: "Tired of copy/pasting from Claude Code into Slack so your coworker can paste it into their agent?" https://github.com/AgentWorkforce/relay
- **Fleet orchestrators on trending.** `stablyai/orca` (110,360 stars) runs Codex, Claude Code, OpenCode, and Pi in parallel worktrees with a mobile companion. It posted +9.8K in week 43 per https://youraiproject.com/github-trending-history/2026/43 . `paperclipai/paperclip` (108,732) is "the open-source app everyone uses to manage agents at work." `mvschwarz/openrig` (8,307) defines persistent teams of Claude Code, Codex, and Pi agents in YAML. It hit #3 on the 2026-09-30 daily board with +622: https://gitstock.org/trending/2026-09-30 . Ageshio's week-40 write-up: "This week's trending repos were overwhelmingly about taming the chaos of AI coding agents: managing fleets of them": https://ageshio.dev/weekly/2026-W40/
- Other September examples: `nightly-labs/openbot` ("agent-to-agent collaboration" between Codex, Claude, and Grok, 3,981 stars), `yetone/cumora` (team chat where agents are teammates, 4,056), and `HarnessRouter/harnessrouter` (one API over Codex, Claude Code, Hermes, PI, and DSH via a "Unified Harness Protocol," 3,777). Source: `gh search repos --created ">2026-08-01"`.

### Inference
- Plenty of people want this, and most solutions are local-only toys (tmux, files, SQLite on one machine). The gaps HN commenters name are delivering messages into an agent mid-turn (push, not poll), identity across machines and teams, durable history, and keeping stale listeners from burning tokens. A judge who has used Claude Code's built-in messaging will ask what a demo adds beyond it. Claude Code now covers push delivery and cross-machine messaging between **one user's own Claude sessions** (see the correction above), so "cross-machine" and "push" alone are weak pitches. The answers that still hold are **cross-vendor** (Claude to Codex to a custom OpenAI agent), **cross-user/team** (built-in messaging is limited to one account and one OS user), **structured, durable, shared state** (built-in messaging is plain text, capped at a 50-message queue, with no shared history), and **non-Claude or API-key agents**. Those are the gaps Agent Relay plus Durable Actors cover.

## 2. The harness wars: the agent runtime becomes an embeddable, long-running service

### Verified
- **DeepSeek Harness** (`deepseek-ai/deepseek-harness`), launched 2026-08-13 under MIT. Its tagline is "Everything is a plugin," built on the Cordis framework. Models, tools, sessions, sandboxes, loops, orchestration, and UI are all plugins. It starts with `npx @deepseek-ai/dsh web`. Now **266,045 stars**. VentureBeat reported "roughly 27,500 GitHub stars and 2,000 forks as of Aug. 13" (re-checked): https://venturebeat.com/technology/deepseek-harness-launches-as-open-source-rival-to-claude-code-alongside-v4-pro-on-api-with-higher-prices . The Register highlights its append-only session log with resume, fork, and replay (not re-checked; VentureBeat's launch piece does not mention it): https://www.theregister.com/ai-and-ml/2026/08/14/deepseeks-innovative-harness-treats-everything-as-a-plug-in/5288095 . A whole plugin cottage industry followed (dsh-desktop 16,992 stars, dsh-TUI, dsh-context, dsh-wallpaper-engine, "4,200+ DeepSeek Harness Plugins"): https://githubtrends.app/weeks/2026-W39/
- **OpenCode 2.0** (Oct 12). Per a secondary write-up, a local background service now owns sessions and tools, and terminal, web, and desktop are clients. It adds `@opencode/sdk` as an embeddable runtime that can be run "on platforms such as Cloudflare Durable Objects," plus Code Mode and background subagents: https://tech-insider.org/opencode-2-0-background-service-launch-2026/ . I have not checked the Durable Objects claim against OpenCode's own docs. Repo `anomalyco/opencode` has 223,118 stars.
- **Vercel Labs fx**: a 6.3 MiB Zig coding agent "built to be scripted or embedded," with ACP and a WASM `libfx` build. Open-sourced per InfoQ on 2026-10-22: https://www.infoq.com/news/2026/10/vercel-zig-fx-agent/ (repo `vercel-labs/fx`, 3,666 stars).
- **Cusp 0.1** (Oct 21): an any-model agent that reads `AGENTS.md`/`CLAUDE.md`/`.claude/settings.json` in place and keeps sessions as append-only, rewindable logs. "Crew, AI teammates with a role, goals, a schedule and a budget" is still on the roadmap: https://cusp.run/blog/introducing-cusp
- **Mercury CLI** went Apache-2.0 on Oct 26: https://mercury-cli.ai/notes/mercury-cli-goes-open-source/ . **ZCode** (Z.ai) launched 2026-09-20 with 8,369 stars: https://github.com/zai-org/ZCode
- **HN harness discourse**: "Harness Engineering 101: The LLM is the brain, the harness is the body" (132 pts, 66 comments, 2026-10-19, marked [flagged]; one commenter advises skipping "AI-slop explanations" and to "build your own basic coding harness from scratch"): https://news.ycombinator.com/item?id=50151390 . Google Research's Harness² (81 pts): https://news.ycombinator.com/item?id=50151059 . Neuralwatt measured uncached input across clients ranging from "1.6% (deepseek-harness) to 11.1%," and found "every cache break in our lab came from a harness editing something it had already sent": https://news.ycombinator.com/item?id=50124642

### Inference
- Every major harness is converging on **long-lived session objects with an append-only event log, many clients, and resume/fork/replay**. That is an actor with durable state. A Terse Durable Actor per agent session (or per task) fits where the ecosystem is heading. It is not a forced sponsor integration.

## 3. Platform launches: agents as deployable code (Oct 2026)

### Verified

An agent is a folder (`instructions.md`, `tools/`, `skills/`, `mcp-connections/`, `channels/`, plus `subagents/`, `hooks/`, `schedules/` per the project-layout reference). It wakes on GitHub/GitLab/Bitbucket PR, comment, and CI events, on Slack mentions and DMs, on webhooks, and on cron. ## Hackathon implications

**What to build (ranked by fit with the tracks and the trends):**
1. **Cross-vendor "coven" of coding agents.** Claude Code, Codex, and a custom OpenAI worker coordinate over **Agent Relay** channels and DMs. Each agent session or task is a **Terse Durable Actor** holding state: claimed work, inbox cursor, budget, and an append-only log. A live web "séance board" streams who is working on what, who is blocked, and messages in flight. It aims at both track prizes and the "both" bonus, and fills the gaps HN commenters name: cross-vendor, push delivery, durable history, identity.
2. **Budget-aware agent factory.** Lead and worker agents where an actor per agent enforces token and turn budgets and routes work to cheaper models (GPT-6.1 Sol or Luna on the $100 OpenAI credits). The on-screen "quota ghost" shows burn in real time. It answers the loudest complaint of October.
3. **Attention / approval broker.** One actor per pending approval, fanned out to phone or browser in real time, with agents asking each other before asking the human. It goes after approval fatigue (Offrun, coucou, nodeterm).

**Gotchas:**
- **Don't make the demo depend on Claude subscription quota.** Limits are draining unpredictably (issues since Oct 16), and SDK/headless use drains the five-hour window about 1.7x faster. Use API keys with the provided OpenAI credits for parallel workers, and keep a recorded fallback.
- **Name collision.** An unrelated "agent-relay" Show HN prototype appeared Oct 27. Say "Agent Relay (agentrelay.com)" explicitly in the demo and README.
- **Agent Relay versions are moving fast** (v14 Oct 13, v15 probe tags Oct 29 and 30). Pin the version you test on Friday.
- **Have a clear answer to "Claude Code already has SendMessage / agent teams."** Don't lead with "cross-machine" or "push." Built-in messaging already does both for one user's Claude sessions (via Remote Control). Lead with cross-vendor (Codex/OpenAI/Mastra agents in the same channel), multi-user/team, structured durable shared state in an actor, and observability.
- **Approval prompts stall autonomous demos.** Pre-configure permission rules and sandboxes so agents don't hang waiting for a human mid-demo.
- **The rules say all code is written at the event.** Prepare only the idea, accounts, and installed CLIs.

**Setup before Oct 31:**
- Install the Agent Relay CLI (`curl -fsSL https://raw.githubusercontent.com/AgentWorkforce/relay/main/install.sh | bash`), run `relay init` in a scratch folder, then open Claude Code and ask it to message `codex-<folder>`. That gets two different agents exchanging a message across two terminals. Make an Agent Relay Cloud account (the README says "You don't need a credit card").
- Run the Terse quickstart (https://docs.useterse.ai/quickstart) once so you know how actor state and real-time subscriptions work. It needs Bun 1.4.2+, then `bunx terse-cli@latest install`, `terse init counter --template counter`, `terse actor dev` (local server on 127.0.0.1:7100), and `terse actor generate` for the typed client. State uses `@Persisted` / `@Emittable` decorators and `this.broadcast()`. Note that installing tools and running a throwaway template is setup, while project code must be written at the event.
- Get Codex CLI (0.166.0, released Oct 29) authenticated with an API key, and update Claude Code to a version with cross-session messaging so you can compare against it.
- Decide your model routing and budget per agent in advance.

**What judges and sponsors likely want (inference):** Hosts want their primitives to be essential to the demo, not decoration. Coding-agent fleets that coordinate in real time are the most "now" story of this quarter, judging by trending, HN, and vendor launches. Supabase's "scale to millions" prize suits a design where one durable actor per agent or session scales horizontally and state is persisted. Mastra and OpenAI credits fit a custom worker agent in the fleet.
